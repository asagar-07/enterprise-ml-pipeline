# Enterprise ML Pipeline with Experiment & Prompt Tracking

## Project Overview

This project simulates an **enterprise-grade ML platform** for credit card fraud detection.

It combines:
- end-to-end ML pipeline orchestration
- experiment tracking
- model versioning
- API-based model serving
- prompt versioning with A/B testing for LLM workflows

The system is designed to reflect how modern ML + LLM systems are built in production environments.

 - This project separates fraud prediction from explanation generation.
 - The ML model predicts whether a transaction is fraud or not fraud.
 - The LLM explanation is generated separately using a visible prompt template (v1 or v2) exposed through the API docs.
 - This explanation is a prompt-based interpretation of the prediction, not the model’s true internal reasoning.

## 🧠 Key Capabilities

### ML Pipeline
- Data ingestion → validation → transformation → training → evaluation
- Config-driven pipeline execution
- Modular pipeline stages

### Experiment Tracking
- MLflow integration for:
  - parameters
  - metrics
  - artifacts (models, plots)

### Model Serving
- FastAPI-based inference service
- Dockerized deployment

### PromptOps (LLM Layer)
- Prompt versioning (v1, v2)
- A/B testing with weighted routing
- MLflow tracking for prompt runs
- Analytics endpoint for version distribution

- The explanation is generated by an LLM using a structured, version-controlled prompt that includes the model’s prediction and input features. The ML model itself does not generate explanations.

### Prompt Templates & Explanation Caveats
This project separates fraud prediction from explanation generation.

How it works
-	1.	The ML model predicts whether a transaction is Fraud or Not Fraud based on input features (Time, Amount, V1–V28).
-	2.	A Large Language Model (LLM) generates a natural-language explanation using a selected prompt template.
-	3.	Prompt templates are exposed via the API:
```bash
GET /prompt/templates
POST /prompt/explain
```
Users can choose between:
 -		v1 — baseline explanation prompt
 -		v2 — structured prompt with constraints on interpretation

Important Caveat

The explanation is not generated by the ML model.
	•	The ML model provides only the prediction.
	•	The LLM generates an explanation based on the prompt + input data + prediction.

Because of this:
	•	The explanation may sound convincing but does not reflect the model’s true internal reasoning.
	•	Features V1–V28 are anonymized engineered variables, so their real-world meaning is unknown.
	•	Unconstrained prompts (e.g., v1) may lead to speculative or misleading explanations.

ML Experiments

Prompt Tracking
	•	Each /prompt/run creates a run
	•	Logs:
	•	prompt version
	•	prompt text

	•	metrics (length, etc.)


🔁 Prompt Versioning Design
	•	Prompts stored in YAML (prompt_config.yaml)
	•	Multiple versions supported (v1, v2)
	•	Traffic split defined via weights
    •   Routing is handled dynamically at runtime.


Example:
        traffic:
            v1: 0.7
            v2: 0.3


🧪 A/B Testing
	•	Weighted random routing
	•	Tracks version usage via MLflow
	•	Analytics endpoint summarizes results
